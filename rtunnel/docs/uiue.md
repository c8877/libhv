# UI / UE 设计

管理台（`relay/admin/web`）和设备本地页（同一份 `DeviceView.vue` 的 `src/local` 入口）
共用这套设计。本文写“为什么这样排”，具体实现约束在根目录 `AGENTS.md` 的
「前端组件规则」里，改页面前两份都要看。

目标不是“好看”，是三件事：**新人在 5 分钟内找到要做的事**、**误操作之前能看清后果**、
**一个页面只有一套实现**。

## 一、原则

1. **按事情分组，不按模块分组。** 用户想的是“我要接一台设备”，不是“我要用
   device 模块”。菜单按对象分，不按后端表分。
2. **框架优先。** 表格、表单、弹层、分页、排序一律用 Element；它的能力不够时用扩展点
   （`sortable="custom"`、`#empty`、插槽），不另写一套。自研替代品丢的是无障碍、键盘
   行为和后续升级。
3. **一屏之内能确认。** 提交前把“装什么、装到哪、会发生什么”用一句话摘要放在按钮旁边；
   不要让人点完再去日志里猜。
4. **能点的地方长得像能点。** KPI、磁贴、行内链接必须是 `router-link` / `el-button link`，
   不做“看着像卡片、其实是死块”。
5. **状态要显性。** 加载、空、失败、无权限、部分成功各有各的样子，不共用一句“暂无数据”。
6. **信息密度服从可读性。** 12px 说明文字可以，但对比度必须过 WCAG AA（4.5:1）；
   `--el-text-color-secondary` 在白底只有约 2.9:1，所以 `.muted` 单独取了一档。
7. **两端同源。** 设备本地页不是“另一套页面”，差异只能放在构建入口、API 适配和权限层。

## 二、设计基线

所有数值来自 `src/style.css` 与 `src/layout/AppLayout.vue`，改的时候改这两处，不要在页面里
写死另一套。

| 项 | 值 | 说明 |
|---|---|---|
| 侧栏宽 | `232px`（`--app-nav-width`） | ≤959px 收起为抽屉 |
| 顶栏高 | `64px`；手机 `56px` | 吸顶，含当前页/刷新/主题/账号 |
| 内容区留白 | `24px`；手机 `12px` | `.page` 的 `--page-pad` |
| 卡片 | 圆角 `12px`（手机 10px）、内边距 `18px`（手机 14px）、间距 `16px` | `.panel` |
| 基础字号 | `14px` | 表格 13px、表头 12px、卡片标题 16px |
| 圆角 | 控件 8px、小标签 6px、弹层 14px | 统一走 Element 变量 |
| 断点 | `1100 / 959 / 900 / 760 / 599` | 959 收侧栏、900 双列变单列、599 手机 |
| 主题 | 浅色 + `html.dark` | 只用 Element CSS 变量与 `color-mix`，不写死灰度 |

字号只用四档，字体两类（正文 + 等宽），不要再造：

| 用途 | 字号 / 字重 |
|---|---|
| 页面卡片标题（`panel-head h2`） | 16 / 650，`flex:0 0 auto` + `nowrap`（防被右侧控件挤成两行） |
| 正文、表格单元格 | 14 / 400（表格 13） |
| 表格表头、次级标题 | 12 / 600 |
| 说明、时间、附注（`.muted`） | 12 / 400，对比度 ≥ 4.5:1 |
| 等宽（设备 ID、路径、命令、Token） | `.mono`，`ui-monospace` |

宽度工具类 `.w90`–`.w340` 是全局的（`style.css`），页面不要再写 scoped 版本——
以前每页各写一份，漏写的页面（OTA、中继列表的 `w140`）下拉框会撑满整行，把标题挤折。

## 三、信息架构

登录后的首页是 **AI 助手**（`/`），仪表盘在 `/overview`。侧栏按对象分 8 组：

| 组 | 内容 |
|---|---|
| 工作台 | AI 助手、概览 |
| 设备与链路 | 设备、客户端、会话、中继列表 |
| 文件与升级 | 文件仓库、分发、任务、Agent 升级 |
| 接入与自动化 | 部署、作业、自愈 |
| 组织与权限 | 租户、管理台账号、接入账号、权限组、授权对象、字典库 |
| 用量与费用 | 用量、费用 |
| 开放接口 | API Token、接口文档、使用指南 |
| 系统 | 告警、证书、审计、设置 |

规则：

- **显示名只有一处**：`router.js` 的 `meta.title`。`shared/nav.js` 只写结构、图标、权限键，
  不再写 `label`；同一个名字两处维护，必然有一处过期。
- **组标题与菜单项同一套排版**：12px / 500，颜色 `rgba(148,163,184,.78)`，高度 34px。
  扁平组（工作台）也要有组标题，否则它的菜单项直接顶在 logo 下，会被读成“更大的组名”。
- **扁平项与二级项同一缩进**：图标和文字落在同一条竖线上（`padding-left: 30px`）。
- **空组自动隐藏**，默认只展开当前页所在组；没权限的菜单不出现，路由守卫再校验一次。
- 手机上底部固定四项高频入口：**助手 / 设备 / 告警 / 概览**，按权限过滤；
  其余走汉堡抽屉。底部栏 `56px` + `safe-area-inset-bottom`，页面底部要留出等高的 padding。

## 四、页面骨架

```
┌──────────┬──────────────────────────────────────────────┐
│ 品牌      │ 顶栏：当前页 / 刷新 / 主题 / 账号            │ 64
├──────────┼──────────────────────────────────────────────┤
│ 工作台    │  .page（自己滚，24px padding）               │
│  助手     │  ┌ .panel ─────────────────────────────┐    │
│  概览     │  │ .panel-head  h2 …… spacer …… 操作   │    │
│ 设备与链路 │  │ 内容（表格/表单/卡片）               │    │
│  ……      │  └─────────────────────────────────────┘    │
│          │  ┌ .panel ─────────────────────────────┐    │
└──────────┴──────────────────────────────────────────────┘
```

- **一个页面 = 若干 `.panel`**，一个 panel 只表达一件事。页面级动作放第一个 panel 的
  `.panel-head` 右侧，不要浮在页面角落。
- **滚动容器是 `.page`**，页面里不要再套 `el-scrollbar` 做第二层滚动；也不要把输入框
  `position: sticky/fixed` 吸在底部（AI 对话页就是反面教材改过来的）。
- 二级页（设备详情、文档、分发）在内容顶部给「← 返回」，一级页不需要面包屑式返回。
- 设备详情：摘要条 + 单层 tab 一起吸顶；`?tab=` 与 URL 同步，刷新/前进后退保持。

## 五、五类页面范式

### 1. 列表页（最常用）

必须包含，从上到下：

1. `.panel-head`：标题（做什么）+ 计数/说明 + 右侧主操作（新建/上传/刷新）。
2. 工具条：搜索 + 状态筛选 + 其他过滤。**状态筛选用 `el-radio-group` + 计数**，
   `el-tabs` 只用于不同数据维度（如「主机 / 记录」），不用于状态。
3. `el-table`：表头 12px，行 13px；数值列右对齐；操作列固定宽度。
4. 分页：`el-pagination`，默认 20 条（设备/账号/Token/作业/告警），审计 50，用量 30，
   分发/OTA 10。
5. 空状态：`el-empty :image-size="70"`，一句“为什么空”+ 一个可执行按钮
   （“从「部署」装一台”“清除筛选”）。

规则：

- **先筛全量再切片**：前端分页也要在全量数据上排序/筛选，不能只排当前页。
- **排序走 `sortable="custom"` + `@sort-change`**，用 `shared/tableSort.js` 的
  `NUM_ORDERS` / `TEXT_ORDERS`；数值列默认降序、文本列默认升序。
- **操作列收敛**：只留一个主操作，其余进「更多」`el-dropdown`（测试/编辑/删除）。
- 危险操作（删除、下线、轮换）要二次确认；确认文案写对象名，不写“确定吗”。
- 批量操作在表格底部出现，不要在顶部再放一套。

### 2. 详情页

- 顶部摘要条：身份（ID/名称）、状态、版本、连接信息、更新时间。
- 单层 tab，非活动 tab **不挂载不请求**，首次进入才加载，之后保留状态。
- 每张卡片只放一类信息；卡片标题用 `panel-head h2`，右上角放该卡片的动作。
- 只读项与可编辑项视觉上要能区分：只读用文本 + `.muted` 注释，可编辑用控件。
- 设备本地页与管理台详情是同一份 `DeviceView.vue`，差异只允许：`mode`、API 适配、
  权限（本地页没有 relay 会话，能力/采样/串口配置只读）。

### 3. 表单页 / 表单弹层（以「部署」为范式）

按「**目标 → 内容 → 参数**」分节，每节一句说明：

```
① 目标主机   主机选择 / 扫描网段 / 测试连接 → 结果内联成标签行
② 安装内容   组件（radio）+ 安装包（版本·架构·变体·体积）
③ 接入参数   设备 ID / relay 地址 / 端口白名单 ……
高级（折叠） 安装目录 / 是否接管 systemd
─────────────────────────────────────────────
摘要：agent 1.4.157（x86_64） → root@10.0.0.21:22 → /opt/rtunnel/agent · 安装并接管服务
                                              [取消] [开始部署]
```

- 必填项 ≤ 6 个；不常用的收进「高级」折叠，默认收起。
- **选中即校验**：选主机后自动探测，结果（架构/systemd/root/剩余空间/已装版本）
  内联展示；包架构与目标不一致就地告警，提交前再确认一次。
- **按钮状态表达完整性**：关键项没选时提交按钮 `disabled`，摘要行说明缺什么。
- 校验用 `el-form` + `rules` + `validate()`，不要手写 `if (!x) ElMessage.warning()`。
- 保存后只提交改动项（设置页按组编辑），不要整表回写。
- 长任务（部署/OTA/分发）：后台作业 + 抽屉看实时日志，可取消；日志跟随到底，
  用户往上翻过就不再打扰，并提供“复制日志”。

### 4. 文档页

- 正文用 `components/MarkdownView.vue`（内核 `shared/markdown.js`），文档是
  `src/docs/*.md?raw`；不要在 `.vue` 里拼 HTML，也不要引第三方 markdown 库。
- 正文宽度限制在 ~76 字符，代码块可横向滚动；站内链接写 `[权限组](#/groups)`，组件会走路由。
- 长文档左侧给页内导航（`el-anchor`），并且**必须拦掉默认跳转**——hash 路由下
  `<a href="#set-3">` 会被当成一次导航跳到不存在的路由。

### 5. 对话页（AI 助手）

- 消息按普通 `v-for` 追加，滚 `.page`；不要内部 `el-scrollbar`，不要吸底输入框。
- 离开底部时右下角出现「回到底端」；新消息到达时若用户没上翻则自动跟随。
- 头部只放高频动作（历史、新对话），低频动作（模型设置）收进「更多」下拉。
- 工具调用、作业确认卡、规则草稿都要能在历史会话里原样还原。
- 助手不能用“问死”式交互：没有工具也要能回答能力问题，不能让用户自己拆问题。

## 六、状态与反馈

| 状态 | 表现 | 禁止 |
|---|---|---|
| 加载 | 表格/卡片 `v-loading`；按钮 `:loading` 并禁用重复提交 | 整页白屏、按钮无反馈 |
| 空 | `el-empty` 70px + 原因 + 下一步 | 只有“暂无数据” |
| 无权限 | 说明缺哪个权限键、找谁开；菜单直接不显示 | 403 报错弹窗 |
| 失败 | 就地 `el-alert` / 表单下方错误，写原因 + 怎么办 | 只弹一句“操作失败” |
| 部分成功 | 单独状态（如“部分完成”），与成功分开计数 | 归到成功 |
| 长任务 | 进度 + 步骤 + 日志抽屉 + 取消 | 同步等待、只转圈 |

细节：

- 破坏性操作的颜色只用 `danger`，且不能在主按钮位置（主按钮永远是安全动作）。
- 「取消」永远在左，「确定/提交」在右；弹窗标题写对象，不写“提示”。
- 轮询只在页面可见且停在该页时进行；离开页面停止（告警 15s、事件流 SSE 同理）。
- 断线不要静默：WebSocket/SSE 断开要有横幅提示并提供“重连”。

## 七、排版、颜色与可读性

- 只用 Element CSS 变量与 `color-mix()`，不写死十六进制灰度，保证深浅色都成立。
- `.muted` 是 12px 的次级文字，颜色取 `primary 68% + bg`，白底对比度 ≥ 4.5:1；
  **不要**直接写 `--el-text-color-secondary`（约 2.9:1）。
- 颜色不单独承载信息：成功/失败同时有文字或图标；曲线图必须有图例，不能只靠颜色区分。
- 数值用 `font-variant-numeric: tabular-nums`，表格里右对齐。
- 等宽只用于 ID、路径、命令、Token、版本号；正文里混排等宽会打断阅读。
- 图表：给图例、给时间方向（“左旧右新”），手机上不要藏图例。

## 八、移动端（≤599px）

- 底部四项 tabbar（见 §三），没有汉堡里再找一遍的路径。
- 固定宽度的控件统一 `width:100%`（`style.css` 已处理 `.w140`–`.w340`）。
- 表格：隐藏次要列（修改时间、自启、内存、运行时长），运行时长折到状态下方；
  操作列只保留「下载」+「⋯」；分页只留上一页/下一页 + 当前页/总页数。
- 触控目标 ≥ 40px；行内展开的确认条比弹窗好（不遮内容、不误触）。
- 弹层宽度 `94%`，不要出现横向滚动条；`DeviceView` 的 tab 可横滑。
- 页面底部留 `56px + safe-area` 给 tabbar，否则最后一屏被盖住。

## 九、文案

- 动作用动词：“开始部署”“测试连接”“轮换令牌”，不用“确定”“提交”。
- 说明写“为什么/什么时候用”，不重复字段名：“容器、临时目录或已有自己的启动方式时用”。
- 错误写三段：**发生了什么 → 大概原因 → 下一步**。
  例：“SSH 握手超时：目标 20 秒内没完成密钥交换（端口可能不是 SSH，或被中间设备拦了）”。
- 不把内部协议名暴露给用户：会话列头写“用户 / 设备”，不写 `A 用户:a_sid`。
- 中文用全角标点；中英文之间留一个空格；单位用 `KiB/MiB`，时间用本地时区并标出来。
- 按钮文案不超过 6 个汉字；同一动作全站同名（“部署”不要一处叫“安装”）。

## 十、组件规约

| 需求 | 必须用 | 禁止 |
|---|---|---|
| 数据表 | `el-table` / `el-table-column` | 手写 `<table>`、自绘排序箭头 |
| 服务端排序 | `sortable="custom"` + `@sort-change` | 只排当前页 |
| 表单校验 | `el-form` + `rules` + `validate()` | 提交前手写 warning |
| 输入/下拉/开关 | `el-input` / `el-select` / `el-switch` | 原生控件 |
| 弹层 | `el-dialog` / `el-drawer` / `ElMessageBox` | 手写遮罩 |
| 分页 | `el-pagination` | 自绘页码 |
| 菜单 | `el-menu` / `el-dropdown` | 手写列表菜单 |
| 成员穿梭 | `el-transfer` | 自己拼双列 checkbox |
| 锚点 | `el-anchor`（并拦默认跳转） | 手写 scrollIntoView 目录 |

确实没有对应能力时才自建，并在代码里标注原因：
`<!-- ui-allow: 原因 -->` 或 `// ui-allow: 原因`。表格排序、表单校验、弹层、tab、分页
不属于可放行范围。`rtunnel/shared/web/*.js`（fs/svc/storage/table-ui）只作为 Vue 卡片内部的
渲染内核，不能再拿它写页面级表格或弹层。

## 十一、设计决策记录

| 决策 | 原因 |
|---|---|
| 首页是 AI 对话而不是仪表盘 | 运维第一反应是“问一句”；仪表盘信息多但不知道从哪看，挪到「概览」 |
| 概览顶部是“待处理”磁贴 | 打开管理台是为了处理异常，不是为了看总量；磁贴可点直达对应页 |
| 告警独立成页，不只放事件流 | 事件流刷新即失，无法确认/追溯；独立表 + 确认状态才能闭环 |
| 状态筛选统一 radio + 计数 | 之前 tabs/纯文字/灰底计数/select 四种形态，同一件事要重新学 |
| 审计补“结果/对象”两列 | 审计的价值是区分“谁做成了”和“谁被拒了”，之前两者长得一样 |
| 部署页分节 + 摘要行 | 一次要填 7 个字段，不分节就会漏；摘要让人提交前能复核 |
| 分发页给文件选择器 | 菜单点进去提示“缺少文件参数”是死路，入口必须能独立成立 |
| 手机底部四项 | 高频页在抽屉里点两下太绕；四项是访问分布的前四名 |

## 十二、改页面前的自检

- [ ] 用的是 Element 现成能力？自建的地方有 `ui-allow` 和原因？
- [ ] 空/加载/失败/无权限四种状态都有？
- [ ] 分页/排序是“先全量再切片”？筛选项带计数？
- [ ] 危险操作有二次确认，文案带对象名？
- [ ] 说明文字对比度过 AA？没有写死颜色？
- [ ] 手机 390px 宽下没有横向滚动、tabbar 不遮内容？
- [ ] 导航显示名只改了 `meta.title`？
- [ ] 跑了 `npm run check:ui` 与 `npm run build`？
- [ ] 改了行为就补了 `rtunnel/tests/ui/{admin,local}/` 用例并登记到 `run-ui.sh`？
