# 接入账号详情页（设计稿）

状态：已实现；Token 配置为行内展开表单（§7.6），账号信息为表格原地转表单（§6.4）  
关联：`docs/design/account-token.md`、`docs/admin/permission.md`

---

# 1. 一句话

把「接入账号」从列表里的行内展开改成独立详情页：上半张卡片看账号本身，下半张卡片管理该账号名下全部 Token。

# 2. 现状与问题

当前 `#/access` 是单页列表，点击行在表格里插入一行展开区：

```
接入账号
├── alice   启用   3   [有效权限] [停用] [删除]
│     └── 展开：Token 表格（9 列）+ [新建 Token]
└── bob     停用   1   ...
```

问题：

```
详情与列表混在一起   展开行把外层表格撑高，列宽和窄屏都受影响
Token 表 9 列        在 1100px 下必须横向滚动，操作列容易被挤出
没有编辑入口         后端 PUT /client-tokens/:id 支持改限额，页面只有停用/轮换/吊销
账号信息不完整       最近使用 IP、创建人、更新时间、权限摘要都没有展示
深链不可用           无法把某个账号发给同事
```

# 3. 信息架构

```
#/access                    接入账号列表
   │  点击行 / 详情
   ▼
#/access/:id                账号详情
   ├── 卡片一 账号信息       KV 表格 + 账号级操作
   └── 卡片二 Token          状态筛选 + 数据表格 + 行内展开表单
```

列表页只保留「找人」和「新建账号」，所有账号与 Token 的变更都收进详情页，避免两个入口各改一半。

```
已确认的边界
  接入账号    有独立详情页（本设计），两张卡片
  Token       没有独立详情页；只在卡片二里以「行内展开表单」编辑配置
  列表展开    不保留；行点击直接进详情，列表不渲染 Token
```

# 4. 路由与导航

```
注册    Router.register(/^#\/access\/(\d+)$/, AccessAccountDetailPage, '账号详情')
匹配    放在 /^#\/access$/ 之后，避免被列表规则截走
高亮    Router.renderNav 用 indexOf(hash) === 0，详情页自动高亮「接入账号」，无需改导航
返回    页面左上角「← 接入账号」+ 浏览器后退
```

参数约定：

```
: id 必须是十进制数字；非数字落到 404
: 账号不存在 → 页面内 404 态：账号不存在或已删除 + [返回接入账号]
: 网络错误 → 加载失败 + [重试]
```

# 6. 卡片一：账号信息

## 6.1 字段

| 位置 | 字段 | 取值 | 说明 |
|---|---|---|---|
| 左 1 | 用户名 | `username`，等宽字体 | 不可改，与客户端 `--user` 一致 |
| 右 1 | 状态 | `UI.status(status, ACC_STATUS)` | 启用 / 停用 |
| 左 2 | 账号 ID | `id` | 方便对接口和日志 |
| 右 2 | 展示名 | `display_name` 或 `—` | |
| 整行 | 备注 | `note` 或 `—` | 超过 2 行截断，`title` 全文 |
| 左 3 | 创建人 | `created_by` 或 `—` | |
| 右 3 | 创建时间 | `UI.time(created_ms)` | 遵循个人时间格式 |
| 左 4 | 更新时间 | `UI.time(updated_ms)` | |
| 右 4 | 最近使用 | `UI.time(last_used_ms)` + ` · ` + `last_used_ip` | 无记录显示 `—` |
| 整行 | Token | `3 个（启用 2 / 停用 1 / 已吊销 0）` | 点击无跳转，就在下方卡片 |
| 整行 | 权限摘要 | `分组 2 · 设备 3 台 · TCP 22,80 · 文件 ro · Shell 否` | 来自 `/effective` |

权限摘要超长时（比如端口很多）截断为一行，`title` 放全文；点「有效权限」看完整结果。

## 6.2 数据来源

```js
const [account, eff] = await Promise.all([
  Api.get('/api/v1/client-accounts/' + id),
  Api.get('/api/v1/client-accounts/' + id + '/effective'),
]);
```

`/effective` 已经存在；`GET /client-accounts/:id` 是本次唯一新增接口（见 §9）。

## 6.3 账号级操作

| 按钮 | 可见角色 | 行为 |
|---|---|---|
| 编辑资料 | manager / admin | 表格原地转表单：改状态、展示名、备注；用户名/账号 ID/时间等保持只读 |
| 有效权限 | operator 及以上 | 复用现有有效权限弹窗 |
| 停用 / 启用 | manager / admin | 二次确认；停用会踢掉在线连接，提示「该账号所有 Token 立即失效」 |
| 删除账号 | admin | 底部分隔线右侧，危险按钮；要求输入用户名确认 |

删除确认：

```
┌ 删除接入账号 ──────────────────────────────────────┐
│ 将删除 alice：                                     │
│   · 3 个 Token                                     │
│   · 2 个分组成员关系                               │
│                                                    │
│ 此操作不可恢复。请输入用户名确认：                 │
│ [ alice                                          ] │
│                                                    │
│                          [取消]  [删除]（未匹配禁用）│
└────────────────────────────────────────────────────┘
```

账号被停用时，卡片顶部插入一条提示条：

```
账号已停用，名下 3 个 Token 均无法接入；重新启用后立即恢复。
```

## 6.4 账号信息原地转表单

点「编辑资料」不弹窗，同一张 KV 表切换成编辑态：可改字段的单元格换成控件，只读字段仍按文本渲染，
表尾多一行提示。卡片右上角的按钮同时换成「取消 / 保存」。

```
┌ 账号信息 ─────────────────────────────── [取消] [保存] ─┐
│ 用户名    alice              状态       [ 启用        ▾ ] │
│ 账号 ID   12                 展示名     [ Alice           ] │
│ 备注      [ 产线采集机                                    ] │
│ 创建人    root               创建时间   2026-11-11 14:02    │
│ 更新时间  2026-11-11 14:20   最近使用   2 分钟前 · 10.0.0.21│
│ Token     3 个（启用 2 / 停用 1 / 已吊销 0）                │
│ 权限摘要  分组 2 · 设备 3 台 · TCP 22,80 · 文件 ro          │
│ 用户名不可修改；保存后立即生效。                            │
└─────────────────────────────────────────────────────────────┘
```

```
可编辑    状态（switch 开关）、展示名（input）、备注（textarea）
只读      用户名、账号 ID、创建人/时间、更新时间、最近使用、Token、权限摘要
表结构    不变；可编辑单元格内放控件，表格列宽不变
按钮      编辑中隐藏「编辑资料 / 有效权限 / 停用」和底部删除区，避免半途改其它状态
提示行    表尾一行，停用会用 warn 色提示「名下 N 个 Token 全部失效」
保存      PUT /client-accounts/:id（display_name / note / status）
取消/Esc  有改动先确认；确认后回到只读表格
并发     编辑期间暂停 5s 刷新；切 Token 编辑或筛选时先确认放弃
```

命名和 Token 行内表单一致：只读数据行不动，编辑控件放在行内，收起即恢复。

# 7. 卡片二：Token

## 7.1 筛选

```
[全部 3] [启用 2] [停用 1] [已吊销 0]
```

```
计数来源   当前账号的 Token 列表，前端统计，不额外请求
默认       全部
排序       后端返回顺序：id 倒序（新建在前）
空结果     显示「该状态下没有 Token」，切回全部可看其它状态
筛选状态   保存在页面实例里，5s 自动刷新后不丢
```

## 7.2 列定义

| # | 列 | 渲染 | 宽度 |
|---|---|---|---|
| 1 | 名称 / 前缀 | 名称加粗；下一行 `token_prefix` + `…`，等宽、muted，`title` 放完整前缀 | 24% |
| 2 | 状态 / 到期 | 第一行状态徽标；第二行到期时间，已过期用 bad 色「已过期」 | 15% |
| 3 | 流量 | 第一行进度条 + `12.4 GB`；第二行 `/ 50 GB · 每月 · 25%`；不限时显示 `/ 不限` | 26% |
| 4 | 频率·并发 | 第一行 `60/分 · 8`；第二行 `突发 10`；0 显示「不限」 | 13% |
| 5 | 最近使用 | 第一行相对时间；第二行 IP（muted） | 13% |
| 6 | 操作 | 编辑（展开表单行）/ 停用（启用）/ 轮换 / 吊销 | 9% |

> 现有行内表把「名称、前缀、状态、到期、流量、频率、并发、最近使用、操作」拆成 9 列；详情页合并为 6 列，窄屏压力明显下降。

## 7.3 流量单元格

```
配额 0          已用 12.4 GB / 不限
配额 > 0        ████████░░░░ 12.4 GB
                / 50 GB · 每月 · 25%

< 80%           进度条用 --accent
80% – 99%       进度条用 --warn
≥ 100%          进度条用 --bad，文字追加「已用完」
已吊销          整行 muted，不画进度条，显示「—」
```

进度条宽度按 `min(100, used * 100 / quota)`，最小可见宽度 2px，避免 0% 时完全消失。

## 7.4 状态与操作矩阵

| Token 状态 | 徽标 | 可否接入 | 可用操作 |
|---|---|---|---|
| active，未过期 | 启用 / ok | 是 | 编辑、停用、轮换、吊销 |
| active，已过期 | 启用 + 到期显示「已过期」/ bad | 否 | 编辑、停用、轮换、吊销 |
| disabled | 停用 / info | 否 | 编辑、启用、轮换、吊销 |
| revoked | 已吊销 / bad，整行 muted | 否 | 无 |

```
operator        不显示任何操作按钮，只能看
manager / admin 除「删除账号」外的全部操作
revoked 行      仍保留在列表里，方便查历史用量和吊销时间
```

## 7.5 空态

```
还没有 Token
客户端需要 Token 才能接入，点右上角「+ 新建 Token」创建。
```

新建成功后：

```
创建弹窗关闭
  → 一次性明文弹窗（复用现有 acc-secret 样式，含复制和示例命令）
  → 关闭明文弹窗
  → 卡片二刷新，新 Token 出现在第一行，筛选切回「全部」
```

## 7.6 行内展开表单（快速编辑）

点操作列「编辑」，在**当前数据行下方插入一个独立的表单行**。数据行本身保持只读：单元格里不出现
输入框，名称、状态、流量等字段仍按文本渲染，只是多出一行 `tok-edit-row` 承载表单。不弹窗、
不跳页，保存后立即生效。新建仍用弹窗，因为需要一次性展示明文。

```
与「行内编辑」的区别
  行内编辑      把单元格本身换成输入框，行高、列宽随编辑态变化
  行内展开表单  数据行原样保留，额外插入一行表单；列宽不动，收起即恢复
```

只读行与表单行的关系：

```
只读行      <tr class="tok-row">…</tr>，6 个单元格只放文本和操作按钮
表单行      <tr class="tok-edit-row"><td colspan="6">…</td></tr>，紧跟只读行之后
展开        插入表单行；收起移除表单行；同一时刻只有一个 Token 展开
```

```
┌ Token ─────────────────────────────────────────────────────────────────────────────┐
│ [全部 3] [启用 2] [停用 1] [已吊销 0]                            [+ 新建 Token]    │
│ 名称 / 前缀            状态 / 到期       流量                  频率·并发  最近使用     操作       │
├────────────────────────────────────────────────────────────────────────────────────┤
│ 构建机                 ● 启用            ████████░░ 12.4 GB    60/分·8   2 分钟前    [收起]     │ ← 只读行

### 布局

```
展开行        <tr class="tok-edit-row"><td colspan="6">…</td></tr>，与权限页展开行一致
数据行        始终只读，不替换成输入框，不参与表单布局
字段网格      auto-fit minmax(180px, 1fr)：常规 6 列，≤1200px 3 列，≤900px 2 列
字段标签      12px muted，输入框在下
底部          左侧条件提示，右侧 [取消] [保存并生效]
同时只展开一个 Token；切换行前先处理未保存修改
```

### 字段与约束

| 字段 | 控件 | 约束 | 说明 |
|---|---|---|---|
| 名称 | text | ≤64 字符，可空 | 空显示「未命名」 |
| 到期 | datetime-local | 可空 = 永久 | 早于当前时间时提示「保存后立即失效」，允许保存 |
| 流量配额 | number + GB | ≥0，步进 0.1 | 0 = 不限 |
| 周期 | select | total / daily / monthly | 改周期会清零本周期用量 |
| 超限动作 | select | cut / block | cut 断开在线连接，block 只拒新连接 |
| 频率 | number | ≥0 整数 | 0 = 不限 |
| 突发 | number | ≥0 整数 | 0 = 与频率相同 |
| 并发会话 | number | ≥0 整数 | 0 = 不限 |

### 保存行为

```
请求        PUT /api/v1/client-tokens/:id
字段        name / expires_at_ms / quota_gb / quota_period / quota_action
            / rate_per_min / burst / max_sessions
不带 status 避免把停用中的 Token 误启用（后端已按此处理）
成功        折叠表单 → 刷新账号卡片与 Token 表 → toast「已保存，立即生效」
失败        保留表单与输入，底部显示错误，可直接重试
清空配额    输入 0 → quota_gb=0 → 不限
```

三项副作用按条件在表单底部提示：

```
新配额 < 已用流量         保存后立即断开该 Token 的在线连接（cut），
                          或立即拒绝新连接（block）
周期从 total 改为 daily/monthly   本周期用量从 0 重新计算
到期时间早于现在           保存后 Token 立即失效，在线连接被踢
```

## 9.1 新增：账号详情

```

响应：

```json

  "id": 12,
  "username": "alice",
  "display_name": "Alice",
  "status": "active",

  "token_count": 3,
  "token_active": 2,
  "token_disabled": 1,
  "token_revoked": 0,
  "last_used_ms": 1762839600000,
  "last_used_ip": "10.0.0.21"
}
```

`token_count` 与列表口径一致：不含已吊销。

查询：

```sql
SELECT a.id, a.username, a.display_name, a.status, a.note,
       a.created_by, a.created_ms, a.updated_ms,
       (SELECT COUNT(*) FROM client_tokens t
          WHERE t.account_id=a.id AND t.status!='revoked')              AS token_count,
       (SELECT COUNT(*) FROM client_tokens t
          WHERE t.account_id=a.id AND t.status='active')                AS token_active,
       (SELECT COUNT(*) FROM client_tokens t
          WHERE t.account_id=a.id AND t.status='disabled')              AS token_disabled,
       (SELECT COUNT(*) FROM client_tokens t
          WHERE t.account_id=a.id AND t.status='revoked')               AS token_revoked,
       COALESCE((SELECT MAX(t.last_used_ms) FROM client_tokens t
          WHERE t.account_id=a.id), 0)                                  AS last_used_ms,
       COALESCE((SELECT t.last_used_ip FROM client_tokens t
          WHERE t.account_id=a.id
          ORDER BY t.last_used_ms DESC, t.id DESC LIMIT 1), '')         AS last_used_ip
FROM client_accounts a WHERE a.id=?
```

错误：

404  {"error":"account not found"}
400  {"error":"bad id"}

## 10.5 行内展开表单状态机

Token 表单行的状态在页面实例上；账号信息表的状态由 `UI.editTable` 内部持有：

```js
this.editId = 0;          // 当前展开的 Token id，0 表示全部收起
this.editDirty = false;   // Token 表单是否有改动
this.kvEditor = null;     // UI.editTable 实例，isEditing()/leave()/save()
```

```
closed ──点「编辑」──────────────► editing(dirty=false)
editing ──输入───────────────────► editing(dirty=true)
editing ──点「保存」─────────────► submitting ──成功──► closed（刷新 + toast）
editing ──点「取消」/ Esc────────► dirty ? confirm : closed
editing ──点其它行「编辑」────────► dirty ? confirm : 切换 editId
editing ──切换筛选───────────────► dirty ? confirm : closed + 切筛选
editing ──自动刷新 timer─────────► 跳过，不重绘
```

账号信息表由 `UI.editTable` 走同一套状态机，页面只判断 `kvEditor.isEditing()`：

```
closed ──点「编辑资料」──────────► editing, dirty=false
editing ──输入──────────────────► dirty 变化（表尾提示随字段变化）
editing ──点「保存」────────────► confirmSave ──► PUT ──► closed（onSaved 刷新）
editing ──点「取消」/ Esc────────► dirty ? confirm : closed
editing ──点 Token 操作/筛选─────► kvEditor.leave()：dirty ? confirm : 收起后继续
editing ──自动刷新 timer─────────► 跳过，不重绘
```

提交中禁用保存按钮，防止重复 PUT；失败回到 `editing(dirty=true)`，输入不丢。

表单值只在展开时从行/账号读取一次，之后以 DOM 为准，避免刷新把输入改回去。

## 10.6 UI.editTable 标准组件

`admin_ui.js` 里的单条记录可编辑表格。只读与编辑形态由同一份字段声明生成，页面不再写两套模板。

```js
const editor = UI.editTable(host, {
  data,                       // 当前记录
  columns: 2,                 // 每行几组「标签 + 值」，默认 2
  fields: [{
    key: 'status',
    label: '状态',
    span: 1,                  // 占几组；2 表示整行
    cls: 'acc-wrap',          // 值单元格附加类
    view: d => UI.status(d.status, MAP),
    edit: {                   // 没有 edit 即只读字段
      type: 'switch',         // text / number / datetime-local / select / switch / textarea / custom
      id: 'ae-status',
      onValue: 'active', offValue: 'disabled',   // 开关映射到的业务值
      onLabel: '启用', offLabel: '停用',
      value: d => d.status,   // 可选：编辑值不同于 key
      html: (v, d) => '…',    // type=custom 时自定义控件，需带 data-ef
      placeholder, maxlength, rows, step, min, max,
    },
  }],
  actions: headerEl,          // 可选：组件负责渲染视图/编辑两套按钮
  renderActions: (editing, data) => html,
  hint: (values, data) => ({ text, warn }),
  confirmSave: (values, data) => Promise<bool>,
  save: (values, data) => Promise,
  onSaved: (values, data),
  onStateChange: (editing, data),
  dirtyMessage, focus,
  editing: false,             // 初始是否编辑
});
```

```
editor.start()        进入编辑；首个控件自动聚焦
editor.save()         收集 values → confirmSave → save → 退出编辑 → onSaved
editor.cancel()       有改动先确认，再恢复只读
editor.leave()        页面执行其它操作前调用，返回是否已退出
editor.update(data)   只读态换数据；编辑态不覆盖输入
editor.isEditing()    页面据此暂停自动刷新
editor.isDirty()      当前值与进入编辑时是否不同
editor.values()       读取所有 [data-ef] 控件的值
```

约定：

```
同一张表       表格行数、列宽在两种形态下不变，只替换单元格内容
只读字段       保持文本渲染，编辑时仍能看到账号 ID、创建时间等上下文
布尔字段       用 type:'switch'，不要用 select 或裸 checkbox；
               开关文案随勾选即时切换，Enter 只保存、不误切换
按钮           编辑态的保存/取消由 data-edit-save / data-edit-cancel 绑定，
               视图态按钮继续走 data-act + UI.actions
Esc / Enter    Esc 取消；输入框内 Enter 保存（textarea 不拦截）
保存失败       留在编辑态，表尾提示错误，按钮恢复可点
```

后续任何「单条记录表格 → 表单」的页面都可直接复用，不需要再写一遍脏检查与确认逻辑。

## 10.7 表格行内展开表单

`UI.editTable` 用于「单条记录的 KV 表」，列表里的行用它不合适。列表行用一组更小的公共方法：

```js

const html = '<tr class="ui-row-edit"><td colspan="5"><div class="ui-row-edit-inner">' +
  UI.formGrid(fields, data) +
  '<div class="ui-row-edit-foot">…[取消][保存]</div></div></td></tr>';

// 2. 控件渲染与取值和 editTable 同一套
UI.fieldControl(field, value, data);   // text / number / password / select / switch / textarea
UI.fieldValues(root, fields);          // 读回业务值，checkbox 按 onValue/offValue 映射
UI.bindFields(root);                   // 开关文案随勾选更新

// 3. UI.detailTable 支持直接插入整行
rows.push(cells);
if (editing) rows.push(formRowHtml);
```

已使用：管理台「账号」行内编辑（角色 / 状态 / 密码 / 设备范围）、字典管理行内编辑。

### 什么时候用展开表单，什么时候用弹窗

```
展开表单   表格里已有这一行，修改多个字段，且需要保留上下文
           账号、Token、字典项、权限分组

弹窗       新建记录（还没有行可挂）
           一次性产物（Token 明文只显示一次）
           确认类（删除、停用、放弃修改）
           独立工作台（字典管理、有效权限预览、旧 ACL 导入导出）

prompt     只剩单字段、可逆、无需上下文的快捷动作
           绑定设备归属、延长截止时间、输入设备 Web 端口
```

判断标准是「有没有一行可以承载表单」，不是「字段多少」。新建没有行，弹窗合理；编辑已有行就展开在行下方，用户的视线和滚动位置都不丢。

# 12. 边界与异常

```

端口很多                    权限摘要截断 + title；点「有效权限」看全量
账号停用                    顶部提示条；Token 列表照常显示，操作仍可用
Token 到期但状态仍 active   到期列显示「已过期」；relay 已拒绝，页面不自动改状态
配额用尽                    流量列红色「已用完」；轮换或等周期重置
并发编辑                    后写覆盖，无版本号（与现有页面一致）
5s 刷新时正在输入           行内展开表单展开期间暂停自动刷新，收起后补刷
表单展开时改筛选            有未保存修改先确认，确认后收起并切换
新配额低于已用流量          表单底部警示；保存后按 quota_action 断开或拒绝新连接
```
