# ACL 设备分组开发规划

对应设计：`docs/acl.md`

## 阶段 1：分组管理

- [x] SQLite 表：`dev_groups` / `dev_group_members` / `dev_group_caps` / `subject_groups`
- [x] 分组 CRUD API
- [x] 设备加入/移出分组
- [x] 能力策略保存
- [x] 管理员/客户端账号加入分组
- [x] 分组列表与详情页面
- [x] 设备列表显示分组
- [x] 有效权限预览 API

验收：

- 分组可创建、改名、删除；
- devid 可加入多个分组；
- 分组能力可保存并回显；
- 设备页显示所属分组。

## 阶段 2：管理台权限（已完成，scope_all 待补）

- [x] 管理台设备列表按账号分组过滤
- [x] 设备详情/文件/分发/终端按设备范围校验
- [ ] `scope_all` 全局管理员
- [x] 无权限返回 403
- [x] 审计分组与授权变更

验收：

- viewer 只能看到分组内设备；
- 直接访问范围外设备详情失败；
- 分组变更后新请求立即生效。

## 阶段 3：A 侧 ACL（已接入，旧 ACL 导入待做）

- [x] relay 加载分组快照
- [x] OPEN 按 devid + 端口检查
- [x] OPEN_SHELL 按 shell 能力检查
- [x] TTY 按 tty 模式检查
- [x] 分组变更投递 relay 线程热更新
- [ ] 旧 ACL 导入 `legacy:<user>` 分组

验收：

- 客户端只能 OPEN 授权设备和端口；
- 多分组权限并集；
- agent caps 仍是硬上限；
- 旧 ACL 导入后行为不变。
