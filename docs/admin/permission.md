# 管理台权限页设计

对应设计：`docs/permission.md`

## 1. 入口

侧边栏（当前）：

```
概览
设备 C
权限
客户端 A
接入账号
会话
证书
账号
文件
任务
审计
设置
```

路由：

```
#/permission
```

旧 `#/acl` 保留兼容，跳转到 `#/permission`。  
ACL 文件改为只读来源，页面右上角「旧 ACL」提供导入与导出。


### 字段

```
名称        必填，同类分组唯一，≤64
描述        可选，≤256
客户端用户  来自 clients.txt 或管理台 client 账号列表
ACL         客户端分组 → 设备分组
```

### ACL 编辑器

行结构：

```
设备分组 | TCP 端口 | Shell | TTY | 文件 | SYSINFO | 指标 | 配置 | Web | 移除
```

- 设备分组：下拉选择，已添加的不能重复。
- TCP 端口：显示已选端口 chips，点击「编辑」打开端口穿梭框。
- Shell：复选框。
- TTY：显示已选 TTY chips，点击「编辑」打开 TTY 穿梭框。
- 文件：`none / ro / rw`。
- SYSINFO / 指标 / 配置 / Web：复选框。
- 移除：删除该 ACL 条目。

保存时整组提交：

```
PUT /api/v1/permission/client-groups/:id
{
  "name": "研发组",
  "description": "...",
  "users": ["alice","bob"],
  "acl": [
    {
      "agent_group_id": 1,
      "ports": [1, 2],
      "shell": false,
      "ttys": [4],
      "file": "ro",
      "sysinfo": true,
      "metrics": true,
      "config": false,
      "web": false
    }
  ]
}
```

```

│                                                              │
```


输入规则：

```
分隔符     中英文逗号、换行、空格均可
去重       输入内重复只保留一个
已存在     标记“已存在”，跳过，不报错
非法值     标记红色，阻止整批提交
端口       1–65535，支持 a-b 范围
TTY        安全字符，支持 *
名称       默认等于值，可用名称前缀批量生成
```

错误示例：

```
┌ 解析结果 ─────────────────────────────┐
│ 22          ✓ 新增                    │
│ 99999       ✗ 端口超出范围            │
│ 80-70       ✗ 范围起始大于结束        │
│ tty USB     ✗ 含非法空格              │
└───────────────────────────────────────┘
整批不会提交，修正后再保存。
```

提交：

```
POST /api/v1/permission/dict/ports/batch
{ "values": ["22","80","443","8000-8100"], "name_prefix": "" }
```

原子性：

```
全部合法 → 全部写入
任一项非法 → 整批拒绝
已存在项 → 跳过并返回 existing 列表
```

#### 删除

单条删除：

```
22  SSH  引用 6  [删除]
→ 被引用，不能删除
```

```
┌ 无法删除 ─────────────────────────────────────┐
│ 端口 22 正被 6 处权限引用                     │
│ 可改为停用，停用后不再参与授权。              │
│ [取消] [停用]                                 │
└───────────────────────────────────────────────┘
```

批量删除：

```
☑ 80
☑ 443
☑ 9000
[删除选中]

┌ 删除 3 项 ────────────────────────────────────┐
│ 80    HTTP    被引用 4 处，不能删除           │
│ 443   HTTPS   被引用 4 处，不能删除           │
│ 9000  MQTT    未被引用，可删除                │
│                                               │
│ 将删除 1 项，跳过 2 项被引用项。              │
│ [取消] [删除可删除的 1 项]                    │
└───────────────────────────────────────────────┘
```

规则：

```
未被引用    允许硬删除
被引用      禁止硬删除，只能停用
批量删除    可删除项执行，被引用项跳过并列出
删除后      从所有穿梭框备选中消失
```

#### 编辑

点「编辑」在字典行下方展开表单，不弹窗：

```
┌ 端口/范围  名称                  ┐
│ [ 8000-8100 ]  [ Web 调试      ] │  值只读，名称/描述/状态可改
│ 描述           状态              │
│ [ 可选      ]  ●——启用           │
│ 停用后，已授权的端口/TTY 立即失效 │
│                     [取消] [保存] │
└──────────────────────────────────┘
```

端口/TTY 值本身不可改；要改值请删除后重建，避免已有引用错位。

#### 引用来源

```
设备分组能力上限
客户端分组 ACL
```

删除/停用前显示引用数量和来源分组。

#### 状态

```
启用    出现在穿梭框备选，可被选择
停用    不出现在备选；已有引用显示“已停用”，不参与有效权限
```

#### 审计

```
dict.port.batch_add
dict.port.delete
dict.port.disable
dict.tty.batch_add
dict.tty.delete
dict.tty.disable
```

### 3.2.3 保存格式

ACL 保存改为字典 ID：

```json
{
  "agent_group_id": 1,
  "ports": [1, 2],
  "shell": false,
  "ttys": [4, 5],
  "file": "ro",
  "sysinfo": true,
  "metrics": true,
  "config": false,
  "web": false
}
```

设备分组能力上限同样使用：

```json
{
  "caps": {
    "ports": [1, 2],
    "ttys": [4],
    "shell": false,
    "file": "ro"
  }
}
```

### 数据来源

左侧候选集由三部分合并，按 devid 去重：

```
1. relay 当前在线 agent
2. admin devices 表登记过的设备
3. 已存在于其他设备分组的历史成员
```

排序：

```
在线优先
最近活跃优先
devid 字典序
```

每行显示：

```
devid
在线/登记状态
已属其他分组（只读标签，不影响加入）
```

已经在当前分组内的设备不出现在左侧。

### 穿梭操作

| 控件 | 行为 |
|---|---|
| `>` | 把左侧勾选设备移到右侧 |
| `>>` | 把左侧当前筛选结果全部移到右侧 |
| `<` | 把右侧勾选设备移回左侧 |
| `<<` | 清空右侧，全部回到左侧 |
| 双击行 | 单台快速穿梭 |
| 复选框 | 多选 |

规则：

- 左右列表都支持搜索。
- 「仅在线」只影响左侧候选。
- 右侧允许包含离线设备；确认时提示。
- 同一 devid 不能重复出现在右侧。
- 当前分组已有成员不进入候选。
- 关闭弹窗不保存；点击确定才提交。

```

```

```
┌────────────────────────────────────┐
│ 从左侧勾选设备后点 [ > ]            │
└────────────────────────────────────┘
```

### 确认

```
[确定添加 3 台]
→ POST /api/v1/permission/agent-groups/:id/devices
   { "devids": ["dev4","dev5","dev6"] }
→ 成功后关闭穿梭框，刷新当前分组行
→ 失败保持弹窗并显示错误
```

后端要求：

- 整批校验；
- 已存在成员幂等忽略；
- 非法 devid 拒绝整批，不产生半写入。

# 12. 运维要点

## 生效时机

```
保存分组 / 字典启停   立即重建规则，只影响新的 OPEN
已建立会话            不受影响，需要断开重连
客户端分组优先        用户一旦在任一分组内，不再看 ACL 文件
```

## 从旧 ACL 迁移

```
1. 权限页 →「旧 ACL」→ 导入，确认预填内容
2. 每个 user= 生成客户端分组 + 导入-<user> 设备分组，能力全开
3. 「有效权限」核对每个用户的设备和能力
4. 按需收紧 ACL 和设备分组上限
5. 最后移除 relay 的 --acl / --acl-file，重启
```

导入只做新增：同名客户端分组或 `导入-<user>` 设备分组已存在时跳过。

## 账号范围

管理台账号（manager / operator / viewer）的设备范围在「账号」页 →「编辑」行内表单维护：

```
勾选设备分组   只能看到这些分组的设备
不勾选         按角色默认：manager 不限，operator/viewer 仅自己绑定的设备
admin          不受范围限制，页面上不提供范围按钮
```

## 字典

```
停用   已授权限立即失效，引用它的 ACL 保留但暂时不生效
删除   被引用的条目会被拒绝，先解除引用
引用   列表中的「引用」= ACL 与设备分组上限里引用该项的数量
```

## 排障

```
看某用户最终权限    权限页 →「有效权限」，输入用户名
看谁改了什么        审计页，事件前缀 permission.* / account.scope
设备侧仍拒绝        检查 agent 的 --allow，设备侧还有一道校验
```

## 备份

单个 SQLite 文件：`--admin-db` 指向的 `admin.db`，连同 `--admin-file-dir` 一起备份。
